# Checkpoint 3.2.4: detector-validation contract and gap audit

Date: 20 October 2026

## Purpose

Checkpoint 3.2.3 showed that the current detector does not produce usable
whole-target observations on the close meadow clip. Before retraining or
changing tracker thresholds, 3.2.4 defines the evidence needed to distinguish
a local failure from a wider detector problem.

This checkpoint does **not** train a model and does **not** modify Baseline A.

## Validation policy

The development validation set must contain these separately reported strata:

1. close drone;
2. medium-size drone;
3. distant/small drone;
4. bird;
5. negative empty sky;
6. negative clutter.

“Medium” and “distant” must ultimately be assigned from labelled target pixel
size, not an unsupported estimate of physical distance. All frames from one
video/capture session must remain together. Predictions cannot be copied into
ground truth, and reviewed negative images must have empty label files.

This is a model-development validation set. The locked test remains untouched.

## Existing-data audit

The earlier v3 extraction was reused rather than duplicated:

- 12 images are present and every image hash matches;
- all 12 come from the same close-drone meadow video;
- none has a completed human-reviewed bounding-box label;
- all 12 still have split `unassigned`;
- medium drone, distant drone, bird, empty-sky negative, and clutter-negative
  strata are absent.

The machine-readable audit therefore reports `ready: false`. This is the
correct result. Training or model selection must not proceed from this set.

## Implemented controls

- A versioned policy in `configs/detector-validation-3.2.4.json`.
- A reusable manifest audit that verifies image existence and SHA-256 hashes.
- Duplicate image-content detection.
- Required scenario-stratum coverage checks.
- Explicit split and annotation-state checks.
- YOLO-label validation for class IDs, field counts, normalized coordinates,
  and positive box dimensions.
- A CLI that writes a persistent JSON audit and exits with code 2 when the set
  is incomplete.
- Unit tests proving both ready and blocked cases.

## Result

**Implementation pass; evidence gate remains closed.** The tooling is working,
but the available evaluation data is not yet representative or annotated.

The next bounded step is not retraining. It is to annotate the 12 existing
close-drone frames as whole aircraft and acquire or select independent media
for the five missing strata. Once those records pass the same audit, model
evaluation can be added without changing the dataset underneath it.
