# Checkpoint 3.2.2: ByteTrack adapter

Date: 19 October 2026

## Scope

This checkpoint implements Ultralytics ByteTrack behind the v3.2 `Tracker`
interface and exercises it only with controlled synthetic observation fixtures.

```text
Frame + SensorObservation records
              ↓
       ByteTrackTracker
              ↓
       LocalTrack snapshots
```

It does not run the detector, process the full meadow video, tune parameters,
compare another algorithm, or persist events.

## Reproducibility decisions

- The internal adapter API is pinned to Ultralytics `8.4.174` because tracker
  internals are not our stable interface.
- Configuration is stored in `configs/bytetrack-3.2.2.json`.
- The initial baseline tracks only class ID `0` (`UAV`). Bird observations are
  not supplied to ByteTrack, preventing the baseline from associating a Bird
  detection into a UAV track.
- The adapter receives saved observations rather than calling
  `YOLO.model.track()`, preserving separation between detector and tracker.
- Every fixture frame must be supplied in increasing order, including empty
  frames. ByteTrack's buffer is measured in processed updates.
- A new external track is `tentative` until it has two matched observations,
  then `confirmed`.
- A retained track with no current match is returned as `lost`, with its last
  real observation and an incremented missed-update count.
- `reset()` clears backend and adapter state for deterministic replay.

## Acceptance checks

- the pinned configuration loads;
- detection-gap replay keeps one track ID;
- lifecycle progresses `tentative -> lost -> confirmed`;
- reset produces the same initial ID on replay;
- repeated, reversed, and mixed-sensor frames are rejected;
- Bird observations are ignored by the UAV-only baseline;
- invalid thresholds and counters are rejected;
- all earlier v3.2, frozen v3.1, and parent v3 tests remain green.

## Result

**Pass.** All 54 v3.2 tests pass. The synthetic gap retains one external track
ID and produces the expected `tentative -> lost -> confirmed` lifecycle. All 31
frozen v3.1 tests and all 10 parent v3 tests remain green. Python compilation
also passes.

No recorded-video result or tracking-quality claim is made at this checkpoint.
