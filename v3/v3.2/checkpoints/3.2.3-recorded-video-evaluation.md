# Checkpoint 3.2.3: controlled recorded-video evaluation

Date: 19 October 2026

## Question

Can Baseline A observations drive the unchanged 3.2.2 ByteTrack adapter on a
short, controlled real-video window?

## Method

- Source: parent-v3 `pexels-drone-meadow-9404253.mp4`.
- Window: source frames 60 through 120 inclusive (61 consecutive frames,
  approximately 2.04 seconds at 29.97 FPS).
- Visual condition: one large multirotor is plainly visible in every frame.
- Detector: the existing Baseline A `yolo26n` checkpoint, image size 640,
  confidence 0.10, CPU, classes UAV/Bird.
- Tracker: the unchanged `configs/bytetrack-3.2.2.json` configuration.
- The detector was run once. All observations and all empty frames were frozen
  to JSON before the tracker was run.
- SHA-256 hashes in the manifest bind the source video, weights, and frozen
  fixture. The replay output separately binds the tracker configuration.

The fixture timestamps represent video-relative time anchored to Unix epoch.
They are deterministic replay times, not claims about the real capture date.

## Measured result

| Measure | Result |
|---|---:|
| Visible target frames (manual review) | 61 / 61 |
| Frames with one or more model observations | 40 / 61 |
| Empty detector frames | 21 / 61 |
| UAV-labelled observation boxes | 82 |
| Boxes at or above ByteTrack's 0.25 new-track threshold | 12 |
| Frames with a reported ByteTrack track | 0 / 61 |
| Confirmed track IDs | 0 |

Manual review found that the boxes localized small aircraft details (often an
arm or rotor light) and background vegetation rather than the UAV as one
object. The above-threshold observations were not spatially and temporally
consistent enough to create a track.

## Interpretation

**The controlled 3.2.3 case fails.** This does not show that ByteTrack is
broken: its synthetic contract and lifecycle tests pass. It shows that the
current detector-to-tracker input is not target-level enough for this clip.
Lowering the tracker threshold would tune against fragmented/false boxes and
is therefore not accepted as a fix.

This is also not evidence about long-range performance. The target here is
large and close, making failure more fundamental: Baseline A was trained on
small-object imagery and does not generalize to this close-view presentation.

## Acceptance checks

- exactly 61 consecutive frames are present and ordered;
- empty frames survive detector export and tracker replay;
- source, weights, fixture, and tracker config are hash-bound;
- the detector is not rerun by the tracker replay;
- result summaries have unit coverage and prior regression tests remain green;
- no tracking-quality metric is claimed without target assignments.

## Next decision

Do not tune ByteTrack on this clip yet. Checkpoint 3.2.4 should define a small,
representative detector-validation set with whole-UAV ground-truth boxes,
including close, medium, distant, bird, and empty-sky examples. That will tell
us whether to retrain the detector, alter preprocessing, or compare a different
detector before tracker tuning.
