# Checkpoint 3.1-B: detector compatibility

Date: 13 October 2026

## Decision

**Pass.** The v3.1 Ultralytics adapter preserves the frozen v3 detector output
for the reviewed frames and settings. It is safe to use the new adapter as the
detector boundary for the next stage.

## Controlled inputs

- Checkpoint: Baseline A `best.pt`
- Checkpoint SHA-256:
  `9dace11fb8f36b971a295de39b6a9bd5f20d3ba51a82defbfd615a89c0b559c5`
- Video: `pexels-drone-meadow-9404253.mp4`
- Frames: 0, 30, 60, 90, 120
- Image size: 640
- Confidence: 0.10
- Device: CPU
- Classes: Bird and UAV
- Absolute numeric tolerance: 0.00001

## Result

- Frames compared: 5
- Equivalent frames: 5
- Legacy detections: 4
- v3.1 detections: 4
- Differences: 0

Both adapters produced four detections on frame 90 and no detections on the
other four reviewed frames. Detection count, class ID, class name, confidence,
and all four box coordinates matched.

The machine-readable record is
`verification/detector-compatibility.json`.

## What this proves

The new module boundary and core record conversion did not change YOLO output
on this controlled sample. The v3 baseline remains available and unmodified.

## What this does not prove

- It does not establish that the four detections are correct.
- It does not measure accuracy, false-alert rate, range, or throughput.
- It does not compare every video frame or every possible backend.
- It does not validate tracking, which has not been implemented.

Those questions require separate evidence and must not be inferred from this
compatibility result.
