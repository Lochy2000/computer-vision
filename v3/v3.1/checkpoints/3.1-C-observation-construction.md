# Checkpoint 3.1-C: observation construction

Date: 14 October 2026

## Scope

This checkpoint adds a pure conversion boundary:

```text
Frame + ordered Detection records -> SensorObservation records -> JSON text
```

It performs no video decoding, model inference, tracking, calibration, file
storage, multi-sensor association, or alerting.

## Contract decisions

- Observation IDs use
  `{sensor_id}:{frame_id}:observation:{detection_index}` to prevent collisions
  when different nodes use the same local frame ID.
- Replaying the same frame ID and ordered detections creates identical records.
- Detection order is preserved.
- Frame ID, sensor ID, and capture timestamp are copied from the frame.
- Bearing and elevation remain unset because no camera calibration exists yet.
- A detection outside the declared frame is rejected.
- Observation JSON serialization performs no file I/O and rejects non-finite
  numeric values.
- Observation IDs are event identities, not persistent track identities.

## Acceptance checks

- deterministic replay;
- source order preservation;
- frame context propagation;
- JSON round trip;
- empty-frame handling;
- out-of-frame rejection;
- non-finite coordinate rejection;
- all previous v3.1 and v3 regression tests remain green.
